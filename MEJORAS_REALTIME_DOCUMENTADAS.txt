1. RESUMEN EJECUTIVO
================================================================================

Se ha implementado una arquitectura completa de tiempo real para la aplicación Aldia
utilizando Laravel Reverb (WebSockets) con las siguientes características principales:

✅ 4 Eventos en tiempo real implementados:
   - NotificationCreated: Notificaciones push a usuarios
   - DeliveryOrderAssigned: Asignación de órdenes a repartidores
   - DeliveryPositionUpdated: Tracking GPS en vivo de entregas
   - MensajeEnviado: Chat en tiempo real entre usuarios

✅ 10 Resources API (DTOs) tipados para serialización consistente
✅ 9 Modelos Eloquent correspondientes
✅ 4 Canales privados + 1 canal de presencia configurados
✅ Autenticación via Sanctum tokens para WebSockets
✅ Rate limiting por tipo de evento (4 tiers)
✅ Presence tracking con TTL de 5 minutos
✅ Suite completa de tests (Unit + Feature + Pest) - 11 archivos de test
✅ Configuración lista para producción (Docker, Redis, SSL)

3. FASE 2: REVERB REAL-TIME ARCHITECTURE
================================================================================

OBJETIVO: Implementar 4 eventos críticos de tiempo real con broadcasting
optimizado y canales seguros.

UBICACIÓN: App/Events/

EVENTOS IMPLEMENTADOS:

3.1 NotificationCreated
   Canal: notifications.{userId} (privado)
   Payload: {id, type, title, message, data, read_at, created_at}
   Uso: Notificaciones push instantáneas al usuario

3.2 DeliveryOrderAssigned
   Canal: delivery.driver.{driverId} (privado)
   Payload: {id, type, order_id, driver_id, assignment_type, status, created_at}
   Uso: Alerta inmediata a repartidor cuando se le asigna orden

3.3 DeliveryPositionUpdated
   Canal: delivery.orders.{orderId} (privado)
   Payload: {id, type, position_id, order_id, driver_id, lat, lng, distance_km, estado_actual, created_at}
   Uso: Tracking GPS en tiempo real para cliente y admin

3.4 MensajeEnviado
   Canal: chat.conversation.{conversationId} (privado)
   Payload: {id, type, conversacion_id, leader_id, mensaje_id, texto, tipo_mensaje, leido_por_usuario, created_at}
   Uso: Chat en tiempo real tipo WhatsApp

CANALES CONFIGURADOS (routes/channels.php):
- notifications.{userId}           → Usuario autenticado = userId
- delivery.driver.{driverId}       → Usuario.repartidor_id = driverId
- delivery.orders.{orderId}        → Usuario.id = orderId (dueño)
- chat.conversation.{id}           → Usuario = comprador_id OR vendedor_id
- presence-conversation.{id}       → Canal de presencia para chat

4. FASE 3: AUTENTICACIÓN Y AUTORIZACIÓN
================================================================================

OBJETIVO: Seguridad completa para conexiones WebSocket con validación
de tokens, políticas de canal, rate limiting y presence tracking.

COMPONENTES CREADOS:

4.1 Servicios (app/Services/)
├── ReverbAuthService.php
│   ├── validateToken(): Valida PersonalAccessToken de Sanctum
│   ├── getUserFromToken(): Obtiene usuario desde token
│   ├── storeConnection(): Registra socket_id por usuario
│   ├── removeConnection(): Limpia al desconectar
│   ├── getUserConnections(): Lista conexiones activas
│   └── isUserOnline(): Verifica si usuario tiene conexiones
│
├── ReverbRateLimiter.php
│   ├── configure(): Registra 4 limiters nombrados
│   ├── checkLimit(): Verifica si excede límite
│   ├── increment(): Incrementa contador
│   ├── remaining(): Intentos restantes
│   └── clear(): Resetea contador
│
└── PresenceTracker.php
    ├── trackJoin(): Usuario entra a canal
    ├── trackLeave(): Usuario sale de canal
    ├── updateLastSeen(): Actualiza timestamp
    ├── getPresence(): Lista usuarios en canal (filtra >5min)
    ├── getUserPresence(): Presencia cross-channel
    └── isUserPresent(): Verifica presencia individual

4.2 Políticas (app/Policies/)
└── ChannelPolicy.php
    ├── joinNotifications(): user.id === userId
    ├── joinDriverChannel(): user.repartidor_id === driverId
    ├── joinOrderChannel(): user.id === orderId
    ├── joinConversationChannel(): user in [comprador_id, vendedor_id]
    └── joinPresenceChannel(): Igual que conversation

4.3 Middleware (app/Http/Middleware/)
├── ReverbAuthMiddleware.php
│   - Extrae bearer token
│   - Valida via ReverbAuthService
│   - Inyecta usuario en request
│   - Retorna 401 si token inválido/expirado
│
└── ReverbRateLimitMiddleware.php
    - Recibe tipo de límite como parámetro
    - Genera key: reverb:{type}:{userId|ip}
    - Bloquea con 429 si excede
    - Incrementa contador automáticamente

4.4 Configuración (config/reverb.php)
- Server: host, port, scheme
- Auth: enabled, provider (sanctum), middleware stack
- Channels: 4 grupos con prefixes, middleware, rate_limit
- Presence: enabled, tracker class, TTL 300s
- Broadcasting: driver reverb
- SSL: configurable via env

4.5 Variables de Entorno (.env.reverb.example)
REVERB_HOST=127.0.0.1
REVERB_PORT=8080
REVERB_SCHEME=http
REVERB_SSL_ENABLED=false
BROADCAST_DRIVER=reverb
REVERB_APP_ID=local
REVERB_APP_KEY=local
REVERB_APP_SECRET=local

8. CONFIGURACIÓN DE ENTORNO
================================================================================

DESARROLLO LOCAL:
-----------------
1. Copiar .env.reverb.example a .env
2. Ajustar REVERB_HOST/PORT si necesario
3. Ejecutar: php artisan reverb:start
4. Ejecutar: npm run dev (Vite + React)
5. Ejecutar: php artisan serve

PRODUCCIÓN (DOCKER):
--------------------
docker-compose.yml debe incluir:
- reverb: imagen laravel/reverb, puertos 8080/8081
- redis: para cache + rate limiting + presence
- horizon: para queue workers (event broadcasting)
- nginx: proxy SSL termination

VARIABLES PRODUCCIÓN:
REVERB_HOST=reverb
REVERB_PORT=8080
REVERB_SCHEME=https
REVERB_SSL_ENABLED=true
REVERB_SSL_CERT_PATH=/etc/ssl/certs/reverb.crt
REVERB_SSL_KEY_PATH=/etc/ssl/private/reverb.key
BROADCAST_DRIVER=reverb
CACHE_DRIVER=redis
QUEUE_CONNECTION=redis

ESCALADO HORIZONTAL:
- Múltiples instancias Reverb detrás de load balancer
- Redis cluster para cache/presence compartido
- Sticky sessions NO requeridas (stateless)
- Health check: GET /health en puerto Reverb
