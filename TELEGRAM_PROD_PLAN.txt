ARQUITECTURA (4 flujos)
1. Vinculacion de canal (deep link + token):
   Canales -> "Abrir Chat en Telegram" -> generateLink crea token
   (32 chars, 15 min, un solo uso, invalida tokens previos del owner) ->
   https://t.me/bot?start=TOKEN -> webhook recibe /start TOKEN ->
   linkAccount valida token (existe, no usado, no expirado, chat no
   pertenece a otro tenant) -> persiste telegram_chat_id.
   [CORREGIDO] El callback del widget ya NO vincula el canal sin token.

2. Login con Telegram (widget HMAC):
   TelegramAuthService::verify valida HMAC-SHA256 (hash_equals) +
   anti-replay (auth_date max 300s) + allowlist de campos.
   Login con email o formulario de email pendiente.

3. Asistente IA por mensajes:
   Webhook -> si chat vinculado -> reenvia a n8n (telegram-proxy) con
   is_linked, tenant_id, bot_token, linking_url. n8n responde al chat.
   TelegramAssistantService (LLM directo PHP) quedo HUERFANO (solo tests).

4. Configuracion global:
   Configuracion Web: bot oficial (token/username/webhook/test), bot login
   (test/disconnect). Tenants usan bot global o personalizado.
