# Real-time Architecture Decision Document
# Generated: 2026-09-06

## Overview
This document outlines the architectural decisions for implementing real-time features in the Aldia application. The application is a Laravel 12 e-commerce platform with customer marketplace, delivery management, and business administration modules.

## Current State Analysis

### Existing Infrastructure
- **Routes**: 771 web routes + 57 API routes
- **Models**: User, Pedido (Order), Repartidor (Driver), Mensaje (Message), NotificationPreference, Conversacion (Conversation), etc.
- **Events**: 15 existing events (DeliveryPositionUpdated, OrderStatusChanged, etc.)
- **Policies**: 5 existing policies (PedidoRecibidoPolicy, etc.)
- **Channels**: 10 existing channels (delivery, chat, orders, etc.)
- **Broadcasting**: Basic setup with log connection
- **Authentication**: Sanctum SPA + API tokens
- **Testing**: 60+ feature tests already implemented

### Real-time Requirements
Four priority real-time features identified:
1. **Live Notifications** - User notifications for orders, payments, low stock
2. **Driver Order Assignments** - Real-time driver assignment to orders
3. **Order Tracking** - Live driver position tracking for customers
4. **Chat Messaging** - Real-time messaging between users

## Phase 2: Reverb Real-time Architecture

### Priority 1: Live Notifications

#### Channel Configuration
```php
// routes/channels.php
Broadcast::channel('notifications.{userId}', function ($user, $userId) {
    return (int) $user->id === (int) $userId;
});
```

#### Event Implementation
```php
// app/Events/NotificationCreated.php
<?php
// ShouldBroadcast implementation
class NotificationCreated implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;
    
    public function __construct(
        public \App\Models\Notification $notification,
        public int $recipientId,
    ) {}
    
    public function broadcastOn(): array
    {
        return [new PrivateChannel("notifications.{$this->recipientId}")];
    }
    
    public function broadcastWith(): array
    {
        return [
            'id' => $this->notification->id,
            'type' => $this->notification->type,
            'title' => $this->notification->data['titulo'] ?? '',
            'message' => $this->notification->data['message'] ?? '',
            'data' => $this->notification->data,
            'read_at' => $this->notification->read_at?->toISOString(),
            'created_at' => $this->notification->created_at->toISOString(),
        ];
    }
}
```

#### Integration Points
- Fire from `Notification::send()` observer or event listener
- Include in `ConversacionObserver` for contextual notifications
- Test with Pest: `php artisan test --filter=NotificationCreated`

### Priority 3: Order Tracking

#### Channel Enhancement
```php
// routes/channels.php
Broadcast::channel('orders.{pedidoId}.tracking', function ($user, $pedidoId) {
    $pedido = \App\Models\Pedido::find($pedidoId);
    if (!$pedido) return false;
    
    // Customer who owns the order
    if ((int) $pedido->cliente_id === (int) $user->id) return true;
    
    // Business owner/admin (tenant scope via BelongsToOwner)
    if ($user->getOwnerId() === $pedido->owner_id && $user->can('pedidos.viewAny')) return true;
    
    // Assigned driver
    if ((int) $pedido->repartidor_id === (int) $user->id) return true;
    
    return false;
});
```

#### Event Enhancement
```php
// app/Events/DeliveryPositionUpdated.php
<?php
// ShouldBroadcast implementation
class DeliveryPositionUpdated implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;
    
    public function __construct(
        public \App\Models\DeliveryPosition $position,
        public int $pedidoId,
        public float $distanciaKm,
    ) {}
    
    public function broadcastOn(): array
    {
        $channels = [
            new PrivateChannel("delivery.orders.{$this->pedidoId}.positions"),
        ];
        
        // Also broadcast to the specific order's tracking channel
        $pedido = \App\Models\Pedido::where('repartidor_id', $this->position->repartidor_id)
            ->whereIn('estado', ['preparando', 'enviado'])
            ->latest()->first();
        
        if ($pedido) {
            $channels[] = new PrivateChannel("delivery.orders.{$this->pedidoId}.positions");
        }
        
        return $channels;
    }
    
    public function broadcastWith(): array
    {
        return [
            'id' => $this->position->id,
            'tipo' => $this->position->tipo,
            'repartidor' => $this->position->repartidor_id,
            'lat' => $this->position->lat,
            'lng' => $this->position->lng,
            'distancia_km' => $this->distanciaKm,
            'timestamp' => $this->position->created_at->toISOString(),
        ];
    }
}
```

#### Integration Points
- Fire from `DeliveryPositionUpdated` event handler
- Include in `ConversacionObserver` for order status updates
- Test with Pest: `php artisan test --filter=DeliveryPositionUpdated`

## Phase 3: Authentication & Authorization for Channels

### Channel Authorization Strategy

#### Gateway-Based Access Control
```php
// app/Providers/AppServiceProvider.php (extensions)

// 1. Notification channels - only authenticated users
Gate::define('subscribe-notifications', function ($user, $userId) {
    return $user->id === $userId;
});

// 2. Driver assignment channels - only assigned drivers
Gate::define('subscribe-driver-assignments', function ($user, $driverId) {
    return $user->repartidor && $user->repartidor->id === $driverId;
});

// 3. Order tracking channels - tenant-scoped access
Gate::define('subscribe-order-tracking', function ($user, $pedidoId) {
    $pedido = Pedido::find($pedidoId);
    if (!$pedido) return false;
    
    return $pedido->cliente_id === $user->id
        || $pedido->repartidor_id === $user->id
        || ($user->getOwnerId() === $pedido->owner_id && $user->can('pedidos.viewAny'));
});

// 4. Chat channels - conversation membership
Gate::define('subscribe-conversation', function ($user, $conversacionId) {
    return $user->can('view', Conversacion::find($conversacionId));
});
```

#### Custom Policies for Channel-Specific Logic
```php
// app/Policies/DeliveryPositionPolicy.php
<?php
// Extended policy for delivery position events
class DeliveryPositionPolicy extends Policy
{
    public function track(User $user, DeliveryPosition $position): bool
    {
        return $position->repartidor_id === $user->id
            || $position->cliente_id === $user->id
            || ($user->getOwnerId() === $position->repartidor->owner_id && $user->can('pedidos.viewAny'));
    }
    
    public function view(User $user, DeliveryPosition $position): bool
    {
        return $this->track($user, $position);
    }
}
```

### Key Test Scenarios

| Feature | Test Cases |
|---------|------------|
| **Notifications** | Auth user receives, unauthorized rejected, payload structure, read receipt |
| **Driver Assignments** | Driver receives on accept, not others, manual assignment, reassignment |
| **Order Tracking** | Customer sees driver, driver sees own, business owner sees, unauthorized rejected |
| **Chat** | Participants receive, typing indicators, read receipts, file attachments |
| **Resources** | JSON structure matches DTO, nested relations, pagination, sparse fieldsets |
| **Policies** | Gates return correct bool, Master/Super Admin bypass, tenant isolation |

## Phase 5: Deployment Considerations

```ini

REVERB_APP_KEY=your_app_key
REVERB_APP_SECRET=your_app_secret
REVERB_HOST=0.0.0.0

```

#### Reverb Server Startup
```bash
# Install Reverb
php artisan reverb:install

# Start Reverb (production)
php artisan reverb:start --host=0.0.0.0 --port=8080

# Queue workers for broadcasts
php artisan queue:work --queue=broadcasting,default
```

#### Monitoring & Health Checks
- Monitor Reverb server health via `/health` endpoint
- Track broadcast latency metrics
- Alert on failed channel connections
- Log all broadcast attempts for debugging
