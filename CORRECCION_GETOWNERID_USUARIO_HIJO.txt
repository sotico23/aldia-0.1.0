2. CAUSA RAÍZ
================================================================================

Master (User 1) tiene creator_id = 1 (auto-referencia circular).

Cuando getOwnerId() camina la cadena creator_id:
  User 10 → User 7 → User 1 → User 1 → CIRCULAR
  Detección circular retornaba $this->id (ID propio del usuario)
  En vez del root owner real del tenant.

Código original (User.php línea 240-241):
  if (isset($visited[$nextId])) {
      return $this->id;  // BUG: retorna ID propio
  }


================================================================================
3. TRAZA COMPLETA DEL BUG
================================================================================

ANTES (con bug):
  User 10 → creator_id=7
    → visit User 7 (creator_id=1)
    → visit User 1 (creator_id=1)
    → CIRCULAR detectado
    → retorna $this->id = 10  ← INCORRECTO

  Resultado: WHERE owner_id = 10 → 0 registros (no existe nada con owner_id=10)


DESPUÉS (corregido):
  User 10 → creator_id=7
    → visit User 7 (creator_id=1), prevRowId=7
    → visit User 1 (creator_id=1), prevRowId=7
    → CIRCULAR detectado
    → retorna prevRowId = 7  ← CORRECTO

  Resultado: WHERE owner_id = 7 → ve productos, almacenes, etc.

5. POR QUÉ NO SE CAMBIÓ MASTER CREATOR_ID
================================================================================

Master (User 1) tiene creator_id=1 (auto-referencia). Originalmente se
propuso cambiarlo a NULL, pero análisis posterior reveló que:

  - Si Master creator_id = NULL:
    → User 7 getOwnerId() retorna 1 (Master)
    → User 10 getOwnerId() retorna 1 (Master)
    → Datos con owner_id=7 NO serían visibles
    → SE ROMPE TODO

  - Con Master creator_id=1 (circular):
    → User 7 getOwnerId() retorna 7 (correcto, tenant root)
    → User 10 getOwnerId() retorna 7 (correcto, tenant root)
    → Datos con owner_id=7 SÍ son visibles
    → FUNCIONA CORRECTAMENTE

La referencia circular de Master es NECESARIA para que el algoritmo
de detección funcione y retorne el tenant root correcto.
